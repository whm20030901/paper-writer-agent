# Day 1 范围冻结与问题清单（P0）

日期：2026-03-25

## 1) 主线场景确认（Scope In）

以下能力纳入本轮 P0/P1 的主线交付：

1. **生成**：输入任务和提纲后产出结构化草稿。
2. **评审**：产出结构、证据、语言反馈与质量分。
3. **修订**：基于 revision notes 进行迭代改稿。
4. **追踪**：可按 run_id 查询结果、质量分、耗时与基础指标。

> 说明：以上四项构成面试演示主流程，不新增额外分支流程。

## 2) 当前能力盘点（As-Is）

### 已具备
- Agent/Pipeline 基础链路（writer/reviewer/gate）。
- FastAPI 服务化接口与前端页面。
- SQLite run 存储、过滤、指标与导出能力。
- LLM 可选接入 + 本地回退。
- 自动化测试基线（pytest）。

### 核心问题
1. **单文件过大**：`paper_writer_agent/api/routes.py` 负责过多 endpoint 与业务拼装，维护复杂。
2. **编排聚合过重**：`paper_writer_agent/agents.py` 承担过多子能力实现，扩展成本高。
3. **文档过长偏罗列**：README 侧重功能清单，主线演示路径不够突出。
4. **执行闭环不足**：此前缺少按日推进机制，任务状态不可追踪。

## 3) 架构边界（Scope Out / Deferred）

以下能力延期到 P2 或后续迭代：

- 向量数据库替换与大规模检索优化。
- 模型路由/评测平台化（多模型自动对比）。
